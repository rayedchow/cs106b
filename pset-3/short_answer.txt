Q1. Looking at a call stack listing in a debugger, what is the indication that the program being debugged uses recursion?
A1. An indication that the program being debugged uses recursion is if the same function name appears more than once in the call stack. That's a sign because it indicates the function is calling itself, and each function fall gets its own frame on the stack but usually with different variables (like n in this example).

Q3. Describe how the symptoms of infinite recursion differ from the symptoms of an infinite loop.
A3. An infinite loop makes the proram keep running forever because nothing ends the loop and it doesn't use any extra memory as it continuously repeats. Inifite recursion crashes instead because each call ends up adding an extra stack frame so the call runs out of the memory and the program has an error like "abrupt ending" or terminated.

Q6. Explain how the recursive structure of `recPower` results in a Big-O runtime of `O(lgN)` relative to the size of its `exp` argument.
A6. 'recPower' results in a big-O runtime of 'O(lgN)' because it makes a single recursive call with exp / 2, so the exponent is halved at every level and reaches teh base case after log_2 (exp) calls. Since each call does a constant amount of work, the total runtime is just O(logN).
